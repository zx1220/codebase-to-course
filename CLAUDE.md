# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is a **Claude Code skill**, not a runnable application. The "source" is `SKILL.md` plus the spec docs in `references/`. When the skill is invoked, it generates a self-contained interactive HTML course from any codebase. The `project/` directory holds the **gallery** (a dashboard of all built courses) plus several **already-built example courses** (`aihot-skill-course`, `anthropic-skills`, `rsshub-course`, `ecc-course`) — these are outputs, not source to edit.

There is **no package manager, no build toolchain, no test suite, no linter**. Everything is plain HTML/CSS/JS plus two bash scripts.

## Commands

```bash
# Build (assemble) a course's index.html from its parts, and auto-refresh the gallery.
cd project/<course-name> && bash build.sh

# Rebuild just the gallery dashboard (project/index.html) without touching any course.
cd project && bash build-gallery.sh
```

`build.sh` is the only build step. It both assembles the course and calls `build-gallery.sh` automatically, so you rarely run the gallery script by hand. To view results, open the resulting `index.html` directly in a browser — there is no dev server.

## Architecture: how a course is assembled

This requires reading four files together to understand.

**The verbatim-copy contract (do not violate).** Every course directory is assembled from five files in `references/`. Four are copied **byte-for-byte** and must never be regenerated or edited:
- `styles.css` → `<course>/styles.css`
- `main.js` → `<course>/main.js`
- `_footer.html` → `<course>/_footer.html`
- `build.sh` → `<course>/build.sh`

Only `_base.html` is customized, with exactly two substitutions: both `COURSE_TITLE` strings, and the four `ACCENT_*` CSS placeholders (pick one palette from the comment block in `references/_base.html`). Everything else (`NAV_DOTS`, `<html>`/`<head>`/`<body>` shells) stays untouched.

**The assembly model.** A course is a directory of partial HTML fragments:
```
project/<course-name>/
  _base.html        ← the <head>/nav shell (open-ended, no closing tags)
  modules/*.html    ← the ONLY hand-written content: each file is a bare
                      <section class="module" id="module-N">…</section> block,
                      no <html>/<head>/<body>/<style>/<script> tags
  _footer.html      ← closes the shell
  index.html        ← NEVER hand-written; produced by build.sh
```
`build.sh` is literally `cat _base.html modules/*.html _footer.html > index.html`. Module order is the shell glob order of the `modules/` dir, so the `0N-` numeric prefix on each filename (`01-intro.html`, `02-actors.html`…) **is** the sequence. The prefix number must match the section's `id="module-N"` (e.g. `01-*` → `module-1`).

**Nav dots are generated, never hand-written.** `main.js` scans `.module` sections at load time and builds the nav-dot bar itself, so it can never drift from the modules. Add `data-nav-title="short"` to a `<section>` only if you want a shorter tooltip.

## The two build paths (a design decision in SKILL.md)

- **Sequential** — simple codebases (single entry point, ≤5 modules). Sketch a one-line mini-brief per module in working notes, then write modules one at a time.
- **Parallel** — complex codebases (full-stack/multi-service, 6+ modules). **Phase 2.5** writes a full brief per module to `<course>/briefs/0N-slug.md` (template: `references/module-brief-template.md`), runs a mandatory coverage check against the Phase 1 extraction list, then dispatches module-writing to subagents in batches of 3. The briefs contain pre-extracted code snippets so writing agents never read the codebase.

In both paths, only the module HTML differs; the five reference files are copied the same way.

## Hard rules when generating course content

- **All course content is Chinese** — titles, body, buttons, tooltips, quiz text, and the plain-language side of code↔translation blocks. The code snippets themselves stay in their original language. (Mandated at the top of `SKILL.md`.)
- **Every course must include all five backbone elements:** at least one group-chat animation, at least one message/data-flow animation, a code↔English translation block per module, a quiz per module, and glossary tooltips on first use of every technical term per module.
- **Code snippets are copied verbatim from the target codebase** with file path + line numbers — never simplified or rewritten.
- Read `references/` files **lazily at the relevant phase**, not upfront (`SKILL.md` › Reference Files lists which phase reads which). This is intentional context management.

## Build notes

- **No course manifest to maintain.** The gallery (`project/index.html`) is generated by `build-gallery.sh` scanning `project/*/index.html` — there is no `courses.json` or registry to keep in sync. Adding a course = building it; the dashboard picks it up automatically.
- **`build-gallery.sh` is portable.** It probes the `stat` flavor (GNU `stat -c` vs BSD/macOS `stat -f`) once up front, so dates are correct on both Linux and macOS. Each course's `build.sh` calls it automatically at the end; a gallery-refresh failure is non-fatal (the course's own `index.html` is still built).
- **Paths in `SKILL.md` are relative to the repo root** (the directory holding `SKILL.md`), so the skill works regardless of where the repo is checked out.
