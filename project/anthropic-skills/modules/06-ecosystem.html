生态与全景图

最后把镜头拉远——看看这 17 个技能怎么组织、怎么分发，以及这套设计背后的开放标准。

先看这座"技能动物园"的全貌

这个仓库（anthropics/skills）不是一个技能，而是17 个技能的集合，外加规范、模板。它的整体结构是这样的：

anthropics/skills/ 整个仓库
skills/ ★ 17 个现成技能（重头戏）
spec/ Agent Skills 官方规范（指向 agentskills.io）
template/ 一个最小可用的技能模板
.claude-plugin/marketplace.json 插件市场的"目录页"

有意思的是，spec/ 文件夹里只有一句话——真正的规范已经搬到了独立网站 agentskills.io/specification。这是个信号：Skill 不再只是 Claude 的私房菜，而是一个跨厂商的开放标准。

17 个技能，分成三个"家族"

仓库的 marketplace.json 把这些技能打包成了三个插件集。每个集合服务一类用户：

📄

document-skills（文档四件套）

xlsx · docx · pptx · pdf。处理办公文档的"生产级"技能，就是 Claude.ai 里"创建文件"功能的内核。源码可见但不开源。

🎨

example-skills（示例集）

12 个演示用技能：算法艺术、前端设计、MCP 构建、网页测试、技能创建器……开源（Apache 2.0），拿来改最适合。

🔌

claude-api（开发指南）

单个技能，专门教 AI 怎么用 Claude API 和各语言 SDK 写应用。

🔍
留意"开源 vs 源码可见"的区别

README 明确说：示例技能是 Apache 2.0 开源（随便用、改、商用）；但文档四件套是"源码可见"（source-available）——能看、能学，但有专门的许可证限制。用之前务必看各自的 LICENSE.txt。这个区别在软件世界很重要。

技能怎么"上架"和"安装"？

关键就是这个 marketplace.json。它像一份"技能商店的目录"，看它的真实结构：

.claude-plugin/marketplace.json 

{
  "name": "anthropic-agent-skills",
  "plugins": [
    {
      "name": "document-skills",
      "source": "./",
      "skills": [
        "./skills/xlsx",
        "./skills/docx",
        "./skills/pptx",
        "./skills/pdf"
      ]
    }
  ]
}
逐行翻译

整个市场的名字叫 anthropic-agent-skills。

下面列出若干个"插件包"（plugins）。

比如这个叫 document-skills 的包。

source 指明代码在仓库哪个位置。

skills 列出这个包包含哪些技能。

用户安装时是按"包"来装的——一次装进四个文档技能。

这种"打包分发"的模式，和手机 App 商店一个思路。

用户在 Claude Code 里只要一句命令就能装：/plugin install document-skills@anthropic-agent-skills。

三扇门，都能用上技能

这套技能系统不绑死某一个产品。同一批技能，三个入口都能用：

💻

Claude Code（终端）

程序员的主场。用 /plugin 命令装技能，还能跑技能自带的脚本、起子代理做对照测试。功能最全。

🌐

Claude.ai（网页）

付费用户已内置文档四件套。也能上传自己的技能。限制是没法跑子代理，所以"对照评测"这类功能用不了。

⚡

Claude API（代码集成）

把技能能力嵌进你自己的应用。适合开发者做产品——比如让你的 App 自动具备"处理 PDF"的能力。

💡
"一次编写，多处运行"的威力

你写一个技能，三个平台都能用。这是因为技能的格式是标准化的（就是前面学的那个 SKILL.md 结构）。标准化带来的复用性，是任何生态系统能壮大的根基——USB 接口、网页的 HTML，都是同一个道理。
