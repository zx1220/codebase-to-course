一个 Skill 的解剖结构

剥开一个 Skill 文件夹，看看里面到底装了哪些零件，各管什么用。

从一个"最小可用"的 Skill 开始

这是仓库里自带的模板（template），一个 Skill 最少需要这些东西：

template/SKILL.md（原文） 

---
name: template-skill
description: Replace with description
  of the skill and when Claude
  should use it.
---

# Insert instructions below
逐行翻译

--- 标记"配置区"开始。

name：技能的唯一 ID，只能用小写字母、数字、连字符（kebab-case）。

description：这是触发开关——告诉 Claude 什么时候该用它。

--- 配置区结束。

下面用 Markdown 写真正的"教学步骤"。

💡
两个必填字段，缺一不可

整个 Skill 系统只认 name 和 description 这两个字段是必须的。其他全是可选。记住这点——它会帮你理解为什么 description 那么关键（Module 4 会专门讲）。

完整的 Skill 长什么样？

当任务变复杂，一个 Skill 就会"长"出更多文件夹。这是仓库里 skill-creator 总结的标准结构：

skill-name/ 整个技能的根文件夹
SKILL.md ★ 必需。配置 + 主说明书
scripts/ 可执行的代码——干"确定性强"的活
references/ 文档，按需才读（省脑容量）
assets/ 输出时要用的素材：模板、图标、字体
evals/ 测试用例，用来验证技能好不好使

注意：只有 SKILL.md 是必需的，其余四个文件夹都是按需添加。简单技能啥都不用加。

scripts / references / assets，有啥区别？

这三个可选文件夹最容易搞混。它们的核心区别在于"谁来执行"和"什么时候被用到"：

⚙️

scripts/

代码亲自干活。适合确定性强、重复的任务——比如"把 PDF 转成图片"。Claude 调用它运行，结果可信。

📚

references/

给 Claude 读的说明书。适合需要判断、灵活应变的场景——比如"各种云平台的部署差异"。Claude 读进脑子的文字。

🎨

assets/

现成的素材。Claude 不需要"理解"它，直接拿来用——比如公司 logo、PPT 模板、字体文件。

🎯
判断技巧：问自己一个问题

"这事是一步一步死步骤吗？" → 用 scripts。"这事需要看情况判断吗？" → 用 references。"这是个现成文件吗？" → 用 assets。

配置区（frontmatter）能写哪些字段？

文件顶部那段夹在三道杠之间的配置区，学名叫 frontmatter。仓库里有个 quick_validate.py 校验脚本，它白纸黑字规定了哪些字段合法。看它的代码就知道规则：

skill-creator/scripts/quick_validate.py 

# Define allowed properties
ALLOWED_PROPERTIES = {
  'name', 'description',
  'license', 'allowed-tools',
  'metadata', 'compatibility'
}

# Check for unexpected properties
unexpected_keys =
  set(frontmatter.keys())
  - ALLOWED_PROPERTIES
if unexpected_keys:
  return False,
    f"Unexpected key(s)..."
逐行翻译

这是脚本里定义的合法字段白名单。

name 和 description——必填，前面讲过。

license（许可证）、allowed-tools（允许用的工具）——可选。

metadata（元数据）、compatibility（兼容性）——可选。

脚本把用户写的字段跟白名单做减法。

只要有多余的字段（比如你手滑写了 nmae）……

校验直接失败，打包都过不了。

⚠️
常见的坑：字段名写错

校验对字段名是严格的。你写 desciption（拼错）或 tools（简写）都会被拒。这是好事——它强迫你写规范，避免 AI 加载时困惑。

看个真实的复杂例子：skill-creator

前面看的是模板。现在看仓库里最"丰满"的 Skill——skill-creator，它把所有可选文件夹都用上了：

skill-creator/ 一个"用来造技能的技能"
SKILL.md 485 行的主说明书
scripts/ 打包、校验、跑评测的代码
references/ JSON 结构说明等深度文档
assets/ 评测评审用的 HTML 模板
agents/ 给子代理的专门指令
eval-viewer/ 可视化测试结果的工具
💡
注意：结构是为内容服务的

skill-creator 这么复杂，是因为它本身要做的事很复杂（造+测+优化技能）。你的海报技能可能只需要一个 SKILL.md 加一个 assets/ 放 logo。从简单开始，需要时再加文件夹——这是仓库里所有技能遵循的原则。
