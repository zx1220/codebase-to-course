四扇窗口：API 端点详解

aihot 一共就开四扇窗，看懂它们就掌握了全部入口

「端点」是啥？把 API 想成一栋大楼

把 aihot.virxact.com 想成一栋大楼。大楼有一个总门（域名），进去之后有好几个窗口，每个窗口办不同的事。这个「窗口」就是 端点（endpoint）。

aihot 这栋楼对外开放四个窗口，全在 /api/public/ 这个楼层下。AI 助手就是个跑腿的，根据你要办的事，去不同的窗口排队。

💡
「公开、匿名」是这栋楼的规矩

这四个窗口全在 /api/public/ 路径下——「public」就是「公开」。不需要登录、不需要 API Key、不需要 token。任何人（任何 AI）带着浏览器 UA 来都能办。这是设计前提：降低使用门槛，让这个 Skill 能跨平台一行装上就用。

四扇窗口，各办各的事

/api/public/daily 最新一份日报（成品报，分 5 版块）
/api/public/daily/{日期} 指定那一天（如 2026-05-07）的日报
/api/public/dailies 日报存档索引（只有日期+头条，不含正文）
/api/public/items 全部 AI 动态（靠参数 mode/since/category 筛）

前三个窗口都围绕「日报」——是已打包好的成品。第四个 items 是原矿池，靠一堆参数自己筛，最灵活也最常用。下面分别拆开看。

items 这扇窗：靠参数「点单」

items 端点是主力窗口，但它不会一股脑全倒给你——你得用参数告诉它「我要什么样的」。这些参数就像点单时的附加要求。

items 的参数表 
# 一条典型请求长这样：
/api/public/items?
  mode=selected       # 精选池（默认）还是 all 全池
  &category=paper     # 只要"论文"那一类（可省）
  &since=<ISO时间>   # 只要这个时刻之后的（默认7天）
  &take=50            # 这次给我 50 条（上限100）
  &cursor=<token>     # 翻页用的"继续上一次"凭证
  &q=RAG              # 关键词搜索（2-200字）
说人话

mode：选「精选」还是「全量」——上一模块讲过的路由。

category：五个分类挑一个：模型/产品/行业/论文/技巧。不填就全都要。

since / take：时间窗 + 这次拿几条。两个一起控制「量」。

cursor：翻页用的「书签」——第一次没有，拿完 API 给你一个，下次带上接着拿。

q：关键词搜索，在标题+摘要里全文匹配。

🧩
参数是「正交」的，能自由组合

这六个参数互不冲突，像乐高积木随便拼。你可以「精选 + 论文 + 最近7天 + 关键词 RAG + 拿50条」五个条件一起叠。这种「每个参数管一件事、彼此独立」的设计叫正交参数——是 API 设计里最舒服的形态，也是你以后给 AI 描述需求时可以用的词：「把这几个筛选条件正交叠加」。

两个容易踩坑的暗号：cursor 和 q

🔖

cursor（翻页书签）

拿第一页时没有，API 回一个不透明的 token；下次请求原样塞回去就拿第二页。SKILL.md 反复警告：别解析、别递增、别跨端点复用——当黑盒。

🔍

q（关键词搜索）

服务端在「标题+中文标题+中文摘要」三列全文匹配，走数据库索引，毫秒级。别再拉一批数据自己 grep——那只能在前 100 条里找，关键词在 100 条外就彻底漏掉。

真身：翻页接龙 
# 第 1 页
resp1=$(curl -sH "User-Agent: $UA" \
  ".../items?mode=all&take=100")

# 从响应里抠出翻页书签
cursor=$(echo "$resp1" | jq -r .nextCursor)

# 第 2 页：原样塞回 cursor 参数
curl -sH "User-Agent: $UA" \
  ".../items?mode=all&take=100&cursor=$cursor"
说人话

第一页请求不带 cursor——从头开始拿 100 条。

用 jq 把响应里的 nextCursor 字段抠出来——这就是「下次从哪继续」的凭证。

第二页请求把 cursor 原样塞进参数，API 就知道接着上次的拿。

hasNext=false 或 cursor=null 时停——没后续了。

⚠️
「不透明 token」是什么意思

cursor 长得像乱码（eyJhIjoxNzgy...），其实是 base64 编码的 JSON，里面藏了「上次拿到哪」。但 SKILL.md 明确说别去解码、别去改它——因为它的内部格式服务端随时可能改，你今天能解析不代表明天还行。把它当一个不透明的黑盒凭证：拿到啥原样回传。这是调用任何带分页 API 的通用生存智慧。
