这是什么：一个把「不能订阅的网站」翻译成 RSS 的同声传译

你天天刷的 B站、微博、推特为什么偏偏订阅不了？答案需要一个「中间人」。

先抛个问题：为什么博客能订阅，B站 却不能？

你可能已经用 RSS 阅读器订阅过博客。但你有没有想过——为什么 RSS 这种好东西，B站、微博、推特偏偏不提供？

因为它们各自只说自己的「方言」，而你的阅读器只听得懂一种「世界语」。中间需要一个翻译——这个翻译就是 RSSHub。

📺
你喜欢的网站（B站 / 微博 / 推特 / GitHub）

各说各的「方言」：有的吐 JSON，有的只有网页。没有一个统一的订阅格式。

📖
你的 RSS 阅读器

只听得懂一种「世界语」：RSS 格式。它不会去 B站 爬数据，也不会读网页——给它 RSS，它才认。

🌐
RSSHub —— 中间的同声传译

你递一个 B站地址给它，它替你去 B站 抓数据，翻译成 RSS，再交还给你的阅读器。这就是它的全部存在意义。

💡
记住这个比喻：RSSHub = 网站翻译官

整个项目的灵魂就一句话——把「不提供 RSS 的网站」变成「能订阅的 RSS 源」。后面所有架构细节，都是为了让这个翻译又快又稳又多语种。

注意 RSSHub 干了哪两件事

它先去抓（替你访问 B站），再翻译（把 JSON 变成 RSS）。这两件事就是后面所有模块要拆的核心——抓取 + 翻译。

拆一条真实的 RSSHub 地址

左边就是那条能订阅 B站 UP 主动态的地址。右边逐段告诉你每一部分在告诉 RSSHub 什么。

地址真身 
https://rsshub.app/bilibili/user/dynamic/2267573
              ─┬────  ────┬────  ────┬──  ───┬───
               │         │          │       │
          服务器地址   命名空间(网站)  路径   参数(用户ID)
逐段翻译

rsshub.app —— 服务器地址：RSSHub 这个翻译官住在哪台服务器上。

bilibili —— 命名空间：告诉 RSSHub「这次要去 B站 这个网站抓」。

user/dynamic —— 路径：要的是「某个用户的动态」这一类内容。

2267573 —— 参数：具体抓哪个 UP 主（这是 B站 用户 ID）。

整条地址粘进任何阅读器，就能刷到这位 UP 主的最新动态——RSSHub 已经替你把 B站 数据翻译好了。

🔑
一个 URL = 一个订阅源

换一个命名空间、换一个参数，就是完全不同的订阅源。RSSHub 用「地址本身」来描述你想要什么——这是它最巧妙的设计，也是理解后面「路由」的钥匙。

RSSHub 凭什么这么好用

它不只翻译一个网站。下面四件事合在一起，才让它成了「万物皆可 RSS」的那个工具。

🌐

1600+ 个网站源

B站、微博、推特、GitHub、知乎、豆瓣……几乎你想得到的主流网站，都已经有人写好了翻译规则，开箱即用。

🔗

一个 URL 就能订阅

不用装插件、不用配账号。把一条 RSSHub 地址丢进阅读器，就开始收更新。地址本身就是「我想要什么」。

⚡

自带 缓存省流量

同一个源短时间内被多次请求时，RSSHub 不会傻乎乎每次都去爬一遍目标网站，而是先返回缓存好的结果，又快又省事。

🛠️

可以自己部署

除了用官方公开服务器，你也能在自己电脑或服务器上跑一份 RSSHub，完全掌控数据和速度。代码是开源的。

RSSHub 是用什么技术搭起来的

下面这些是它 package.json 里的关键 依赖。现在看不懂名字没关系，先记住每个工具「替 RSSHub 干了什么活」。

Hono Web 框架：接收你的请求、分发到对应翻译规则。轻量、快速。
Node.js 运行时：让 JavaScript 能在服务器上跑起来的环境。
TypeScript TypeScript：带类型的 JavaScript，项目大了也不容易写错。
ofetch HTTP 客户端：替 RSSHub「去别的网站抓数据」的那个工具。
cheerio 用来「读网页」：像 jQuery 一样从一堆 HTML 里提取你要的那块内容。
Playwright 浏览器自动化：对付必须真打开浏览器才能抓的网站。
端口 1200 端口：RSSHub 自己部署时默认监听 1200 这个门牌号。

这些工具各司其职，拼起来就是一个能跑的「网站翻译官」。你现在不用记名字——只要知道 RSSHub 用它们完成了「接收请求 → 抓取 → 翻译 → 返回」这一整套活。
